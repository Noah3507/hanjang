# AI 배경 + 보존 상품 사진 — 후속 PoC 설계만

2026-11-27. **이미지 API 호출0, 배경 생성 구현0. B와 계약을 합의하고 별도 승인을 받은 뒤 진행한다.**
현재 사진·템플릿 문제를 배경 생성만으로 해결할 수 있다고 가정하지 않는다.

## 분리한 레이어와 보존 계약

1. `source_photo`: 기존 원본, EXIF/원본 SHA와 소유권 유지. 생성형 모델로 상품을 재해석하지 않는다.
2. `foreground`: 명시적으로 선택한 로컬 마스크와 처리 버전. RGB는 원본에서만 가져온다.
3. `background_asset`: 사진과 별개의 생성 배경 파일/SHA/모델/프롬프트 버전/검토 상태.
4. `local_composition`: 검토된 배경 → 실제 상품 → 로컬 제목·상품명·가격·CTA 순서.
   그림자는 상품 모양에 근거해 로컬 합성하고 상품 RGB/로고를 다시 그리지 않는다.
5. 최종 RGB1080×1350 PNG의 snapshot에는 foreground와 background의 실제 SHA,
   템플릿·합성 정책 버전을 모두 넣는다. 다른 배경/사진의 늦은 결과는 최신 revision으로 게시하지 않는다.

`photo_mode`는 계속 cutout/original 두 가지다. 배경 옵션을 세 번째 사진 모드로 혼합하지 않는다.
cutout은 실제 알파 영역 전체(분리된 구성품 포함)를 보존한다.
original은 사진 자체를 자르거나 배경을 교체하지 않고 기존 whole-photo 카드로 배경 위에 배치한다.
배경과 원본 사진이 어울리지 않으면 기존 배경으로 되돌아가는 명시적 선택지를 둔다.

## 생성 입력과 레이아웃

B가 정하는 템플릿별 metadata에서 상품/텍스트 예약 영역을1080×1350 기준 좌표로 받는다.
카테고리(확정/추정 구분), 광고 목적, 색상 palette, 조명 방향, 배경 재질, 여백 지도를 조합한다.
상품 영역은 물체가 없는 공간/받침 면으로, 텍스트 영역은 낮은 복잡도·대비 확보 영역으로 요청한다.
배경에 음식·잔·병·포장·로고·숫자·광고 문구를 생성하지 않도록 한다.
**금지 지시만으로 중복 상품/문자가 없음을 보장하지 않는다.**
로컬 문자/오브젝트 탐지와 실제 시각 검토로 반려하고, 초기 PoC에서는 승인된 배경만 합성한다.
탐지기가 모든 허위 상품/문자를 찾는다고 주장하지 않는다. 필요하면 예약 영역을 로컬에서 단순화할 수 있으나
이는 B의 아트 디렉션과 함께 비교할 항목이며 이번에는 구현하지 않는다.

초기에는 text-only 배경 생성으로 사용자 사진 전송을 피한다. 상호·상품명·가격·주소·연락처도 전송하지 않는다.
허용된 범주·색상·예약 영역만 서버에서 구성한다. 원문 자유 입력을 모델 지시로 붙이지 않는다.
사진·로고를 image-edit 입력으로 보내는 방식은 기존 짜장면 허가를 재사용하지 않고 별도 권한·비용 승인 대상이다.

## 캐시·편집·서비스 연동

- 배경 key: 모델 snapshot/size/quality/배경 프롬프트 버전/카테고리/목적/팔레트/예약영역/조명·재질/소유권 범위.
  가격·제목·본문·CTA는 key에서 제외한다. 텍스트 편집은 기존 배경 바이트를 재사용하고 이미지 API 호출0회다.
- 상품 교체/목적·팔레트 변경으로 key가 달라져도 **자동 유료 생성하지 않는다**. 기존 배경 적합성 확인 후 명시적으로 요청한다.
- 캐시 hit는 실제 파일 SHA와 접근 권한을 검사한다. 실패/삭제/만료는 원본 상품·기존 성공 광고를 삭제하지 않는다.
- 초기에는 기존24시간 비공개 Job 보존 정책을 따른다. 사진 없는 승인 배경을 장기 공유 라이브러리로 승격하는 정책은 별도 합의한다.
- 기존 Candidate/copy/부분 수정/PNG·PDF 다운로드는 유지한다. PNG가 바뀌면 ranking·diagnostics는 stale로 처리한다.
  가격·카피 편집으로 사진 분석이나 마스크를 다시 만들지 않는다.
- v2/v3 렌더러에 배경 레이어를 전달하는 additive 내부 계약과 템플릿 opt-in은 B와 먼저 합의한다.
  임의 CSS 삽입·frontend 필드 추가·기존 renderer 교체를 이번 PR에서 하지 않는다.

## 이미지 API 후보·가격·지연

공식 자료를2026-11-27에 확인했으며 계정별 접근은 아직 조회하지 않았다. 실제 모델 사용 가능성은 PoC 직전 다시 확인한다.

|후보|공식 가격|사용 판단|
|---|---|---|
|[gpt-image-1.5](https://developers.openai.com/api/docs/models/gpt-image-1.5)|1024×1536 출력 low $0.013/medium $0.05/high $0.20. 별도 text input $5/M, image input $8/M|고정 size·quality의 출력 가격을 계산하기 쉬운 비교 후보|
|[gpt-image-2.6-flare](https://developers.openai.com/api/docs/models/gpt-image-2.6-flare.md)|text input $5/M, image input $8/M, image output $30/M|빠른 반복을 위한 최신 후보. 출력 토큰·복잡도에 따른 비용을 별도로 산정해야 하며 고정 장당 가격으로 표시하지 않음|

GPT-Image-2는 [공식 모델 페이지](https://developers.openai.com/api/docs/models/gpt-image-2)에 deprecated로 표시되어 신규 기본 후보에서 제외한다.
[공식 가이드](https://developers.openai.com/api/docs/guides/image-generation#limitations)는 복잡한 요청이 최대2분 걸릴 수 있다고 설명한다.
이 프로젝트의 실제 p50/p95는 **미측정**이다. 미래 PoC에서 요청 대기·생성·다운로드·합성 시간을 따로 측정한다.
대기 중에도 기존 광고/다운로드는 유지하고, 실패 후 재생성은 자동 재시도가 아닌 별도 승인 요청으로 분리한다.
