## 사실 슬롯의 실제 구현

`templates/v3/collection.html`과 가격형 별도 HTML은 `data-field=store_name/product_name/price_text`를
headline/body/cta와 별도 표시한다. `brand_c`의 반복 상호 장식도 템플릿 책임이다.
현재16종 HTML을 실제 Jinja 상속으로 펼쳐 세 슬롯이 각각 입력 원문을 받는 것을 무료 점검했다.
카피가 이 사실을 매번 다시 써야 하는 구조가 아니다. 템플릿/CSS는 수정하지 않았다.

가격형이 가격을 말하지 않아도 별도 가격칸은 남는다. 생성 카피는 해당 상품을 고를 상황/제공 특징으로
관심을 유도하도록 지시하며 ‘좋은 선택’ 같은 범용 문구만 반복하는 것을 성공 기준으로 삼지 않는다.
그 설득력은 실제 생성 후 판단해야 한다.

## 가격 원문 정책 — 변경 없음

실제 실패의 입력은 ` 3,000원 `, 모델 제목의 직접 가격은 `3,000원`이었다.
숫자 값은 같아도 기존 원문 계약에서 `COPY_FACTS_VIOLATION / rewritten price`로 거부된다.
같은 입력에서 `[[price_text]]`는 공백까지 포함해 ` 3,000원 `으로 바인딩되고 통과한다.
테스트는 이 두 결과를 모두 유지한다. 문구에 가격이 없어도 사실 슬롯이 정확히 표시한다.

프롬프트로 개선 가능한 것은 **placeholder 준수/불필요한 사실 재서술 감소**다.
숫자가 같으면 바깥 공백을 무시할지, 입력을 사전에 정규화할지는 별도 서버 입력 정책·공동 계약 결정이다.
이번에는 그 정책을 정하지 않았고 조용한 trim, 원문 수정, 실패 뒤 수작업 치환으로 우회하지 않았다.
입력 이름80자/긴 가격도 그대로 유지한다. 바인딩 후 headline60자를 넘으면 기존 길이 오류가 유지된다.

## 목적별 조합과 예산 검사

기존 payload의 `ad_goal`을 그대로 사용하고 새 사용자/API 필드를 추가하지 않았다.
`copy_prompt_v8_1.instructions_for(payload)`는 서버 소유 상수에서 **선택된 하나의 목적**만 조합한다.

- menu_promotion: 메뉴에 관심을 갖고 고르기. 직접 주문/방문 요구로 바꾸지 않기.
- store_visit: 매장에 들르기. 메뉴 확인/주문만으로 대체하지 않고 미제공 위치·시간 생성 금지.
- order: 경로를 특정하지 않은 주문 권유. 단순 구경·선택·방문만으로 대체하지 않기.

표현 목록은 고정하지 않으며 제공되지 않은 주문 경로는 기존 validator가 계속 거부한다.
자유 입력을 instructions 문자열에 삽입하지 않는다. 미정의/비문자 목적은 SDK/원장 접근 전에 안전하게 거부한다.
SDK의 실제 instructions와 CopyStore의6000 상한 검사에 같은 resolver를 사용한다.
기존 두 상품/세 목적/상위3단서 조합의 입력 상한은5551~5611로6000 이내다.
긴 특징 입력은 기존 상한을 넘을 수 있으며 조용히 자르지 않고 오류로 알린다.
