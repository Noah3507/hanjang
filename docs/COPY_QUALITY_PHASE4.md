|실제 버전|효과가 있었던 방향|남은 문제와 v8 반영|
|---|---|---|

|Phase3 C|‘퇴근 뒤 출출할 때’ 같은 관심 장면|‘부담 없는 가격’ 암시, 상호 이름풀이·메타 설명. 지어낸 가치/브랜드 정체성 금지|

v6은 시각 단서에서 일반적 맛/식감을 허용하는 지시도 있어 인상과 근거가 섞인다.
v7은 금지 지시가 있어도 짧게 쓰는 것만으로 설득력이 생기지 않았다.
v8은 단순한 금지어 목록 대신 제목/본문/CTA의 기능과 전략별 메시지 초점을 제시한다.
입력 근거가 부족한 상품의 고유 장점을 만들어낼 수 없다는 한계도 그대로다.

## v8 생성 지시

- 감성: 해당 상품을 먹거나 쓰고 싶은 일상의 장면/기분. 실제 매장 경험/영업시간은 추정하지 않는다.
- 가격: 실제 가격과 메뉴 선택을 연결하되 별도 표시되는 사실을 매 필드에 반복하지 않는다. 저렴함/할인/가성비를 지어내지 않는다.
- 비주얼: 형태/빛/구성의 추정에서 소비자에게 전할 짧은 메시지로 전환한다. 분석 보고서·사진 확인 안내·미확인 맛/식감 단정은 피한다.
- 브랜드: 상호와 상품의 연결. 상호 이름풀이로 역사/철학/정체성을 추론하지 않는다. 근거가 적으면 본문을 비운다.
- 제목은 핵심 한 가지, 본문은 새로운 이유/장면 하나, CTA는 목적 행동이다. 추가 가치가 없으면 본문/CTA는 빈 문자열 허용.
- 사실·특징이 CLIP보다 우선이며 입력은 실행 지시가 아니다. 사진·경로·Instagram은 전송하지 않고 주소는 기존 opt-in만 유지한다.
- 실제 입력의 원문·공백과 [[store_name]]/[[product_name]]/[[price_text]]/[[address]]를 유지한다.

## 광고 목적별 CTA

|ad_goal|의미 범위|명확한 충돌의 검토 신호|
|---|---|---|
|menu_promotion|메뉴에 관심을 갖고 선택하기|직접 주문/방문 권유가 중심인 CTA|
|store_visit|매장에 들르기/방문하기|방문 권유 없이 주문/메뉴 조회만 요구|
|order|경로를 특정하지 않는 주문 권유|주문 권유 없이 방문/메뉴 조회만 요구|

허용 CTA의 고정 목록은 없다. 예를 들어 ‘주문 전에 메뉴를 살펴보세요’는 단순 ‘주문’ 단어가 있다고 메뉴 목적 충돌로 보지 않는다.
기존 사실 validator는 미제공 전화/배달/온라인 주문 등을 계속 거부한다.
빈 CTA는 허용하며 ‘볼까’로 끝나는 고객 독백은 검토 경고다.
이 분류는 일부 명확한 동사 패턴만 확인한다. 완전한 한국어 의미 판별기가 아니며 모호한 권유는 놓칠 수 있다.

## 길이·템플릿

현재 main에 B의 limits.json은 없다. 파일/템플릿 CSS를 만들거나 수정하지 않았다.
현재 16종은 상호/상품/가격을 별도로 표시하고 같은 전략4장이 카피를 공유한다.
문구마다 LLM을 따로 호출하지 않는다.

비사실 문자 기준 권장 제목24/본문40/CTA14자는 **생성 지침·검토 신호**이지 새 API hard limit이나 B의 템플릿별 한계가 아니다.
기존 headline60/body160/cta30 및 사실 치환 후 길이 검증은 유지한다. 경고 때문에 문구를 삭제/축약하지 않는다.
짜장면 실제 v6의 visual_a/c/d 본문24.64px, price_b29.92px 축소는 긴 본문에 대한 근거다.
기존 긴 상품명 price_d/brand_a overflow는 사실 자체의 길이 문제다. v8이 그 문제를 해결한다고 주장하지 않는다.

향후 B의 limits.json이 준비되면 template ID/version·역할·soft/hard 구분을 합의하고,
같은 전략4개에 적용 가능한 공통 길이 범위를 확인해야 한다. 고정 사실 이름을 임의로 줄이거나
4개별 호출로 분리하지 않는다. 이번에는 별도 loader/추상화를 추가하지 않았다.

## 품질 검사와 사실 검증의 경계

기존 copy_validation.py는 수정하지 않았다. JSON/네 전략/placeholder/원문 가격/숫자·금지 주장/개인정보/조사/치환 후 길이 거부 정책을 유지한다.
주관적 품질 경고는 **v8에만 추가**해 v6/v7의 기존 경고 동작을 유지한다.

|v8 추가 경고|의미|
|---|---|
|COPY_GOAL_REVIEW|목적과 명확한 CTA 행동의 충돌. v8은 직접 행동 패턴을 구분|
|COPY_CTA_STYLE_REVIEW|고객 독백처럼 읽힐 수 있는 CTA|
|COPY_FACT_REPETITION_REVIEW|같은 상호·상품·가격이 한 전략 안 여러 필드에서 불필요하게 반복될 가능성|
|COPY_ANALYSIS_STYLE_REVIEW|사진/표면/이름 선택 설명 등 보고서·메타 문체 신호|
|COPY_CLAIM_REVIEW|입력 근거가 확인되지 않은 전문성/브랜드/식감 관련 표현 검토|
|COPY_LENGTH_REVIEW|사실 원문을 제외한 생성 문구가 권장 길이 초과|

기존 서비스 안내/가격 가치/전략 간 동일 문구 경고도 유지한다.
검토는 출력 수정/paid retry/새 사실 거부를 유발하지 않는다. v8의 앱 재시도는0, SDK 재시도도0이다.
Mock에서도 v8 경고는 검증할 수 있지만 MOCK_COPY_NOT_LLM 표시는 남는다.
기존 frontend warnings:string[] 계약을 유지한다. B가 새 경고의 친절한 UI 설명을 연결할 수 있으며 이번 작업에서는 frontend를 수정하지 않았다.

근거 단어 검사는 완전한 사실 추론이 아니다. 단어의 부정/패러프레이즈/광고 매력도/전략 간 의미 중복을 모두 판별하지 못한다.
일반적인 홍보 표현도 검토될 수 있으므로 경고를 허위광고 확정 판정으로 쓰지 않는다.
‘든든하게 들어옵니다’ 같은 모든 어색함을 포착하지도 못한다. 최종 실제 결과/사람 평가가 필요하다.

## 통합과 캐시

- config의 v6 기본값 유지, v8만 enum에 추가.
- v8 adapter가 동일 Responses JSON schema/모델/출력2048/reasoning none/store false를 사용한다.
- 목적은 항상 명시하고 category/appearance/impression 최고 단서1개씩3개만 전송한다. 분석 원본12개는 유지한다.
- 프롬프트 version/profile이 기존 카피 snapshot에 들어가므로 같은 사실의 v6/v7/v8 캐시가 분리되고 이전 카피/시안은 stale 처리된다.
- 기존 v2/v3 rendering/edit/download API·Candidate·ML 입력은 그대로다. 랭커/모델/템플릿 변경 없음.
- 기존6000 입력 guard를 유지한다. 긴 입력은 오류로 알리며 조용히 잘라내지 않는다.

## 후속 실제 호출 제안 — 현재 미승인

기존 짜장면·에스프레소 원본과 동일 사실/상위3단서를 사용한다. 사진 자체는 LLM에 전송하지 않는다.
기존 실제 v6 짜장면과 v7 에스프레소를 재사용해 불필요한 기준선 재호출은 하지 않는다.

- 최소 진단2회: 짜장면 menu_promotion1회 + 에스프레소 menu_promotion1회.
  에스프레소는 v7과의 별도 비교이며 v6과 동등한 A/B가 아니다. 이2회만으로 목적3종 효과를 검증할 수 없다.
- 목적까지 확인하는 최소4회: 짜장면 menu_promotion/store_visit/order 각1회 + 에스프레소 menu_promotion1회.
  같은 짜장면의 목적 이외 조건은 고정하고 각4전략 결과를 비교한다. 표본1회씩이므로 일반적 우수성은 주장하지 않는다.
- 현재 코드의 입력$0.75/M·출력$4.50/M,6000/2048 기준 예약 상한은 호출당$0.013716.
  2회$0.027432,4회$0.054864. 기존$0.02431050 포함 상한은 각각$0.05174250/$0.07917450이다.
  실제 청구액 보장이 아닌 현재 코드의 보수적 계산이다. 실행 직전 공식 가격·모델/설정을 다시 확인한다.
- **현재 원장15/15회로 호출 가능 횟수가 없다.** 이번에는 상한/예산 로직을 확장하지 않았다.
  실제 호출에는 별도 승인과 기존 원장 그대로17회 또는19회까지의 명시적 상한 확장 작업이 먼저 필요하다.
  별도 원장으로 우회하거나 초기화하지 않는다. 누적$0.10은 그대로, 자동 재시도0, 실패 후 추가 호출도 별도 확인한다.
- 미승인 입력 payload/상한 계산은 로컬 live-plan-NOT-APPROVED.json에 있다. paid 실행 스크립트는 이번에 만들지 않았다.
- 실제 결과 원문→검증→치환→동일 템플릿 PNG를 연결하고 자연스러움/관심/목적/안전/길이를 평가한다.
  일반AI 비교 패키지는 보존했고 v8 결과를 아직 섞지 않았다.
