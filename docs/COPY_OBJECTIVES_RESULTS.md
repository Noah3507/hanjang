- 원산지·재료·수제·할인·신선도·주문 경로 등의 새 검증 가능한 주장은 발견하지 못했다.

## API 계약 및 B 요청

- PUT/GET /api/v1/jobs/{job_id}/input: 최상위 ad_goal 선택 필드.
  menu_promotion(기본), store_visit, order. 최초 생략은 기본값, 이후 PUT 생략은 저장값 보존.
  null/미정의 값은 422. GET 및 copy-generation 응답에 목적을 명시한다.
- POST copy-generation/rendering의 expected_input에도 GET에서 받은 ad_goal을 포함해야 한다.
  B의 frontend/src/api/copy.ts와 rendering.ts는 현재 필드를 명시적으로 재구성하므로 수정이 필요하다.

- B: uploads.ts의 Draft/saveInput, CopyState 타입, 목적 선택/복원, 두 expected_input 조립부를 연결.
  목적 변경 후 오래된 카피·시안·순위를 최신처럼 표시하거나 편집/다운로드하지 않도록 한다.
- 출력 네 전략/headline/body/cta 계약과 빈 body/CTA 허용은 유지. 새 브랜드 필드는 추가하지 않음.
- v7은 목적과 상위 단서 3개를 명시적으로 전송한다. 원본 분석 12개는 보존한다.
  v6 기본 메뉴 목적은 기존 payload를 유지해 500자 입력과 6000 guard를 회귀시키지 않았다.
  목적은 항상 draft hash에 포함되므로 omission 때문에 캐시 fencing이 약화되지 않는다.
- limits.json은 현재 main에 없음. 계약 확정 시 template ID/version, 고정 정보 역할,
  권장 길이와 hard limit 구분을 B와 합의해야 한다. 임의 템플릿별 최대 길이는 넣지 않음.
- v7 선택 설정: HANJANG_COPY_PROMPT_PROFILE=v7. 운영 .env/서버는 변경하지 않았다.
  실제 운영 전에는 목적 UI, 품질 검토와 별도 호출 예산 승인이 필요하다. 현재 승인 호출은 소진됐다.
