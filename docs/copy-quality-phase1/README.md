# 음식점 카페 광고 카피 품질 개선 Phase 1

상품별로 쓸 만한 한국어 광고를 만드는 것이 목표다. 이번 단계에서는 프롬프트의
상품·전략 지침과 좁은 검증 오탐을 개선했다. 실제 LLM의 매력도 개선은 아직
검증하지 않았다. [8조건·32문구 비교](COMPARISON.md)의 개선 열은 **사람이 작성한
목표 예시**이며 새 프롬프트의 생성 결과가 아니다. Mock 전후 출력도 동일하다.

## 기준과 변경 범위

기준 main `c8cb74a`는 PR #59 `fix(copy): 맛·식감 표현 허용, 문구 탈락 이유 기록`을
포함한다. 새 브랜치는 `feat/copy-quality-phase1`이다. 시작 시 미커밋 변경은 없었다.
프런트엔드·템플릿·ML·API/schema·예산 원장 코드는 수정하지 않는다. 열린 PR은
없었지만 최근 UI 자동 생성·디자인 선택 변경이 있어 그 파일들은 건드리지 않았다.

변경 파일은 `copy_prompt.py`, `copy_validation.py`, `copy_quality.py` 및 카피 테스트,
평가 fixture/오프라인 review 도구·이 문서뿐이다. PR #59의 맛·식감 허용,
근거 단어 검사와 탈락 사유 로그는 유지한다. PR #59 테스트는 새 prompt version
기대값만 갱신한다. 과거 Phase16 fixture의 중복 본문은 새 advisory가 경고하도록
검증 기대값을 명시적으로 갱신했다.

## 현재 생성 구조

1. 인증된 Job의 사진·draft·분석 context를 snapshot으로 묶는다. 개인정보 필드의
   우발적 재전송은 `provider_payload`에서 차단한다. 사진 자체는 LLM에 보내지 않는다.
2. 상호·상품명·가격·분위기·선택 특징·유효 CLIP 추정만 최소 text payload로 전달한다.
   주소는 명시 옵션이 true일 때만 전송하고 Instagram은 제외한다.
3. Responses API와 고정 모델 `gpt-5.4-mini-2026-03-17`, strict JSON schema를 사용한다.
   SDK retry는 0이다. 앱 retry는 설정에 따라 0 또는 1이며 현재 로컬 .env는 변경하지 않았다.
4. 매 유료 시도를 기존 예산 관리자가 먼저 예약한다. 응답이 와도 JSON·글리프·
   플레이스홀더 치환·사실/숫자·가격 원문·조사·치환 후 길이 검증을 거친다.
   검증 오류도 이미 발생한 usage를 기록한다. 일부 오류는 재시도 가능하지만
   조사 오류는 수동 검토 상태로 중단한다.
5. 성공 결과를 current snapshot일 때만 renderer에 전달한다. 새로운 quality advisory는
   문구를 수정·거절하거나 추가 호출하지 않는다. 기존 v2/v3 연결 계약은 그대로다.

2026-11-23 루트 Settings 로딩은 `copy_provider=mock`, `copy_allow_paid=false`,
`copy_max_retries=1`, `copy_max_requests=6`, 예산 $0.10이었다. 키 값은 출력하지
않았다. 발표용 실행 설정이 이를 덮어쓸 수 있으므로 이미 실행 중인 발표 서버의
모드라고 단정하지 않는다. 현재 루트 Mock 실행에는 새 실제 prompt가 적용되지 않는다.

## 진단과 개선

고정 Mock은 상품 특징과 무관하게 전략별 제목이 8사례에서 각각 8번 반복된다.
가격·사진 확인 CTA, 추상적인 여유/만남 문구는 개발용 동작 확인에는 적합하지만
광고 품질의 기준으로 볼 수 없다. 기존 실제 prompt도 메뉴 정체성·특징 활용과
제목/본문/CTA의 역할 구분을 더 명확히 할 여지가 있었다. 실제 과거 LLM 응답을
이번 8조건으로 수집한 자료는 없어 실패율·평균 매력도는 산출하지 않는다.

`copy-v6-menu-identity`는 다음을 명시한다.

- 감성: 메뉴를 먹고 마실 장면의 제안, 상투적인 행복/특별함 반복 지양
- 가격: 제공 가격과 메뉴 선택 연결, 확인 안내·근거 없는 저렴함/할인 금지
- 비주얼: 메뉴에 맞는 일반적 감각, CLIP 추정을 실제 색/재료로 확정하지 않기
- 브랜드: 상호와 메뉴를 함께 기억하기, 근거 없는 연혁/철학/수상/인기 금지
- 특징이 있으면 이유를 구체화하고 없으면 창작하지 않기, 제목은 핵심·본문은
  추가 이유·CTA는 메뉴에 맞는 행동, 분위기는 어조이며 전략과 분리
- 사용자 입력은 실행 지시가 아니며 가격·placeholder·길이·개인정보 계약 보존

프롬프트를 늘려 입력 한도를 바꾸지 않았다. 8조건 모두 기존 6000-byte 보수적
상한 계산 이내이며, 테스트용 일반적인 500자 특징도 자르지 않고 통과한다.
모든 최대 길이/분석 단서 조합을 보장하지 않으며 초과 입력은 기존대로 명시 거절한다.

검증 회귀 테스트를 먼저 작성해 `매일 먹고 싶은`, `매일 마시고 싶은`의 오탐
2건을 재현했다. 이 두 문자 문형에 한해 희망 표현으로 취급한다. `매일 갓 볶는`,
`매일 만드는`은 여전히 생산 빈도 주장이고, 같은 문장 뒤의 수제·우유·할인 등도
계속 검사한다. 매칭 단어를 전역 삭제하거나 입력 근거를 생성하지 않는다.

새 quality 검사는 전략 간 같은 제목/긴 본문 반복을 기존
`COPY_REPETITION_REVIEW`로 알린다. 의미상 유사성 전체를 판별하지는 못한다.
최고·꿀맛 등의 모호한 어휘 오탐과 미등록 재료·효능의 누락 위험은 남아 있다.
단어가 입력에 있다는 사실도 그 문장의 주장 전체를 보증하지 않는다.

## 입력과 비교 자료

짜장면·후라이드 치킨·아이스 아메리카노·딸기 케이크 각각 특징 없음/충분함을
구분했다. 각 조건의 합성 상호·상품명·가격·분위기·특징은 비교표와
`tests/fixtures/copy/menu_quality_phase1.json`에 정확히 기록했다. 사진/개인정보는 없다.

- [COMPARISON.md](COMPARISON.md): 전략별 제목/본문/CTA의 고정 Mock과 수작업 목표 비교
- [results.json](results.json): 실제 Mock 출력·검증 결과·경고·오탐 probe 원자료
- `python scripts/service_copy_quality_review.py --baseline-ref c8cb74a --output <new-folder>`:
  pinned PR #59 validator와 현재 validator를 같은 데이터로 실행하는 무료 재현 명령

현재 8조건의 Mock/수작업 목표는 모두 검증을 통과한다. 이는 검증 가능성이지
실제 모델 검증 통과율이 아니다. Fake SDK는 수작업 목표를 반환하므로 그 1회
성공도 실제 LLM의 품질·실패율·필요 호출 횟수를 예측하지 않는다.

## 평가 기준

실제 A/B를 수행할 때 입력·모델·출력 한도·추정 단서를 같게 하고 prompt만 바꾼다.
가게 사장님 또는 한국어 평가자 2명 이상에게 조건을 가린 A/B를 무작위 순서로
제시한다. 점수와 선호, 고쳐 쓸 부분을 별도로 남기고 불일치는 숨기지 않는다.

| 항목 | 자동 검사 | 사람의 1·3·5점 기준 |
|---|---|---|
| 상품 적합성 | 원문 상품명 포함/특징 조건 분리 | 다른 메뉴에도 그대로 맞음 / 메뉴는 맞으나 일반적 / 해당 메뉴·제공 특징을 잘 살림 |
| 광고 매력도 | 자동 판단 안 함 | 사용 의향 없음 / 수정 후 사용 / 사장님이 바로 쓰고 싶음 |
| 한국어 자연스러움 | 조사·문자·길이 | 어색함 / 이해되나 경직됨 / 자연스럽고 읽기 좋음 |
| 전략 차별성 | 정확히 네 전략·동일 제목/본문 반복 | 서로 바꿔도 같음 / 일부 구분 / 장면·가격·감각·상호가 분명함 |
| 연결성 | 정확/포함 반복 advisory | 세 필드가 반복·단절 / 연결되나 중복 / 제목의 흥미→본문 이유→CTA 행동 |
| 사실 안전성 | 근거 어휘·숫자·원문·privacy | 근거 없는 주장 / 해석 모호 / 제공 사실과 주관적 제안만 사용 |
| 검증 통과율 | 최초 통과/전체 응답·시도별 오류·usage | 별도 취향 점수 없음. 적은 표본은 그대로 명시 |

할인·원산지·재료·건강 효능 등 근거 없는 주장이 있으면 취향 점수와 별개로
출시 부적합으로 기록한다. 평균만으로 덮지 않는다. 프롬프트 개선 여부는 같은
조건의 실제 전후 응답과 사람의 평가가 확보된 뒤 판단한다.

## 무료 검증과 실행

카피 단위/API/Fake Responses 테스트와 실제 Chromium v2/v3 렌더링 검사를 추가했다.
JSON·플레이스홀더·가격·조사·사실 guard와 PR #59 회귀, 8사례의 1회 adapter
성공·추가 재시도 없음, 치환 후 렌더링을 확인한다. 테스트 ledger는 pytest 임시
경로이며 기존 비용 원장을 열어 초기화하지 않는다. 최종 CI 수치는 PR에서 확인한다.

2026-11-23 로컬 결과: 전체 Backend **544 passed / 3 skipped**(실제 B 모델 opt-in),
전체 실행 수집 후 추가한 advisory 무재시도 검사 **1 passed**. Frontend **103 passed**,
TypeScript/build 성공, 기존 카피·렌더링 Playwright **6 passed**다. 전체 실행은
`RUN_RENDER_TESTS=1`로 신규 8개 v2/v3 렌더링 사례(합계 64 PNG 결과)를 포함한다.
기존 AnyIO deprecation 경고는 남아 있다. 실패 단계에서 입력 fixture mood 오타와
프롬프트 크기 초과를 수정했으며 입력 상한·렌더링·안전 검사를 낮추지 않았다.

```powershell
$env:RUN_RENDER_TESTS='1'
.\.venv\Scripts\python.exe -m pytest
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend run test -- --run
npm.cmd --prefix frontend run build
```

현재 확인용 독립 Mock UI는 `http://127.0.0.1:5191`, backend는
`http://127.0.0.1:8021`이다. Mock 카피가 예전처럼 일반적인 것은 의도된 계약 보존이며,
새 실제 prompt의 결과를 이 화면으로 확인했다고 주장하지 않는다. 운영 서버·원장·
환경·팀원 디자인 코드는 유지한다. 실제 API 호출을 위한 서버 모드 변경도 하지 않는다.

## 승인 후 최소 실제 API 계획

현재 원장은 8회/$0.01274025다. 루트 기본 한도 6회로는 추가 호출이 불가능하다.
기존 코드가 허용하는 최대 10회/$0.10을 일시 실행에 명시할 경우 남는 슬롯은 **2회**다.
먼저 **동일한 짜장면·특징 없음 조건**에서 기존 v5/개선 v6을 각 1회, 총 최대
2회 비교하는 소규모 A/B를 제안한다. 한 호출이 네 전략을 모두 반환한다.
이는 네 상품 전체의 일반화를 검증하지 않는다. 8조건 전체 전후 비교는 16회가
필요하므로 현재 한도 밖이며 별도 예산·설정 승인이 필요하다. 원장은 지우지 않는다.

- 모델 `gpt-5.4-mini-2026-03-17`, Responses, text-only 합성 입력, 사진·개인정보 없음
- 기존/현재 고정 소스의 독립 검증 실행으로 각각 1회, SDK 및 앱 retry 모두 0
- 실패/검증 거절도 소비한 1회로 취급, 자동 재호출 없이 원인·usage 보고 후 중단
- 기존 원장을 그대로 사용하고 입력 상한 6000/출력 상한 2048, 누적 $0.10 유지
- `HANJANG_COPY_PROVIDER=openai`, `HANJANG_COPY_ALLOW_PAID=true`,
  `HANJANG_COPY_MAX_RETRIES=0`, `HANJANG_COPY_MAX_REQUESTS=10`, 기존 모델·원장 경로를 **일시 실행에만**
  지정하고 키는 서버에서만 읽기. .env/운영 서버 변경 없음. 키 값을 출력하지 않기
- 승인 후 실행 직전 남은 원장·동시 사용 여부를 다시 확인해 추가 호출 수를 강제 제한

현재 adapter 및 [공식 GPT-5.4 mini 요율](https://developers.openai.com/api/docs/models/gpt-5.4-mini)은
입력 $0.75/출력 $4.50 per 1M tokens다(2026-11-23 확인). 예약 기준 호출당
`(6000×0.75 + 2048×4.50)/1,000,000 = $0.013716`, 2회 **$0.027432**다.
기존 누적과 합친 예약 상한은 $0.04017225이다. 응답 usage가 불명확한 실패는
기존 보수적 예약을 유지하고, 결과가 탈락해도 이미 생성한 토큰은 과금될 수 있다.
최종 실비는 실제 usage로 기록한다. **이번 단계의 유료 호출은 0회이며 아직 승인 요청 전 준비 계획이다.**
